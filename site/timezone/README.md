# Time Together · 时区协作助手

无需构建、后端、账号或第三方服务的静态工具，入口为 `/timezone/`。

## 使用

1. 世界时钟每秒更新，可搜索常用中文城市、英文城市或 IANA 时区名。
   默认展示 22 个常用时区；支持 `Intl.supportedValuesOf` 的浏览器可搜索完整时区列表。
   包含海德拉巴（Hyderabad / `Asia/Kolkata`）、塔林（Tallinn / `Europe/Tallinn`）、
   布拉格（Prague / `Europe/Prague`）及 Redmond（雷德蒙德 / `America/Los_Angeles`）。
   海德拉巴与孟买、新德里共用印度时区，Redmond 与洛杉矶共用美国太平洋时区，
   因此分别合并为同一张时钟卡，避免重复选择同一时区。
2. 点击时钟选择 2–4 个时区，默认北京 / 上海、伦敦、纽约。
   至少保留 2 个，替换时先添加再移除。第一个时区是日期和时间轴的基准。
3. 设置协作日期和每个时区的当地可用时段（默认 07:00–20:00）。
   结束早于开始代表跨午夜，例如 22:00–02:00；起止相同代表全天。
4. 选择最短共同空档（15 / 30 / 60 / 120 分钟）。修改后自动计算，
   也可点击“查找共同时间”。深绿色时间轴与结果卡展示完整可用窗口，
   可在窗口内安排会议，并复制各地日期、时间、UTC 偏移及 IANA 名称。

日期表示**基准时区的完整一天**，其他地区可能是前一天或后一天。
窗口会在基准日的起止边界截断；跨午夜的空档可能分成两段。
可用时间每天重复，不排除周末、节假日，也不读取日历忙闲状态。
时钟使用设备时间，时区规则来自浏览器的 IANA 数据，请确保系统时钟准确、浏览器及时更新。

## 计算与夏令时

`core.mjs` 遍历真实 UTC 分钟，将每个瞬间通过 `Intl.DateTimeFormat`
转换为各地当地日期 / 时间，再判断是否位于每个可用窗口内。
区间为左闭右开，例如 07:00–20:00 不包含 20:00 以后的时间。

- 支持分钟精度、半小时 / 四分之一小时时差及跨国际日期变更线。
- 按所选日期应用夏令时，不使用固定 UTC 偏移。
- 基准日可为 23 / 24 / 25 小时；跳过的当地时间不会制造虚假空档，
  重复的当地时间会按两个真实 UTC 区间分别参与计算。
- 最短时长按实际经过时间计算，结果卡的 UTC 偏移可区分重复钟点。
- 页面日期限制为 2000–2100 年，避免早期历史时区的秒级偏移。

## 隐私与兼容

仅将所选时区及可用时段存入本机 `localStorage`，不保存协作日期。
存储禁用或损坏时退回默认配置。无外部字体、CDN、分析或网络 API。
Clipboard API 不可用时提供已选中的文本供手动复制。
现代 Chrome / Edge / Firefox / Safari，使用 ES Modules，需要 HTTP 服务预览：

```bash
python -m http.server -d site 8000
# http://localhost:8000/timezone/
```

## 验证

从仓库根目录执行：

```bash
npm run test:unit      # 含纯时区计算：冬夏令时、跨午夜、分数时差、跳过/重复钟点
npm run test:timezone  # 使用本机 Chrome/Edge 的桌面 / 移动浏览器检查
```

浏览器未自动找到时设置 `BROWSER_PATH`。可选 `SCREENSHOT_DIR` 输出桌面和移动长截图。
测试仅启动临时浏览器和 localhost 服务，不访问生产工作负载。
